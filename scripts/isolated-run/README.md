# isolated-run — «запустил и изолировано»

Набор для безопасного прогона ARTEX в изолированной VM: единственный egress —
LLM-туннель, каждая попытка наружу видна в журнале. Продуктизация паттерна
artex-bench/vm-lab (relay.py, egress-lock.sh) — там он отработал два прогона
без единого лишнего соединения (BENCH-REPORT.md, 2026-10-23).

## Порядок запуска

1. **Реле на ХОСТЕ** (не в госте!): `python3 relay.py <host-ip> 8443 api.venice.ai:443 canary-relay.log`
2. **Туннель**: `ssh -R 8443:127.0.0.1:8443 vm` — в госте LLM-профиль указывает на
   `https://api.venice.ai:8443`, `/etc/hosts` в госте: `127.0.0.1 api.venice.ai`.
3. **Лок в госте** (root): `sudo ./egress-lock.sh <gateway-ip>` — наружу только
   lo / established / DNS-gw / docker-подсети 172.16/12 (это таргеты лабы,
   без правила лок режет собственные цели). Самопроверки внутри: внешний хост
   недоступен (иначе exit 1), LLM-туннель жив.
4. **Боевые настройки движка**: `./setup-defaults.sh http://127.0.0.1:8787 "$TOKEN"` —
   `llm_record=true` (PUT /api/settings) и `llm_judge_fail_action=deny`
   (PUT /api/intercept/judge — judge-ключи не входят в плоский /api/settings;
   скрипт делает GET-merge-PUT, чтобы не затирать остальные поля). Idempotent.
5. **Задача** — запуск mission обычным порядком.

## Как читать канарей-лог

`canary-relay.log` на хосте — источник истины по egress: каждая строка
`conn#N <ip> open → api.venice.ai:443` … `conn#N close bytes=… dur=…` — это
одно сознательное соединение. Всё, чего в логе нет, не происходило; любой
не-Venice upstream в логе = инцидент. Вторая канарейка — счётчики правил:
`iptables -L OUTPUT -v -n` (DROP-строки должны расти, policy DROP — на месте).

## Откат

`sudo ./egress-lock.sh --unlock` — OUTPUT/DOCKER-USER обратно permissive.
Реле — просто Ctrl-C. Настройки движка не откатываем: llm_record/deny —
боевые значения по умолчанию.

## Известные границы

Root-воркер теоретически может править iptables в госте (лок не является
абсолютным против root внутри той же ОС). Поэтому реле и его журнал живут на
ХОСТЕ, а не в госте: гость не может ни остановить реле, ни подделать/чистить
лог — что бы ни происходило в госте, факт и адрес каждого соединения
зафиксированы снаружи. Пост-чек прогонов: policy DROP на месте + в логе только
api.venice.ai.
