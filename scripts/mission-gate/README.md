# mission-gate — привратник внешних миссий ARTEX

Хостовый слой egress-контроля поверх гостевого iptables: даже если root-воркер
снесёт файрвол внутри VM, наружу (кроме туннеля VPN) ничего не уйдёт, а LLM-путь
вообще не работает без поднятой миссии.

## Состав

- `mission-up.sh <ip>...` — поднять внешнюю миссию: Mullvad connect → проверка
  exit-IP (am.i.mullvad.net, mullvad_exit_ip обязан быть true, иначе abort с
  откатом) → **kill-switch ON** (`mullvad lockdown-mode on`: VPN моргнул —
  трафик блокируется, а не уходит с домашнего IP) → гостю открываются только
  переданные IP (80/443) → armed/strict-маркеры для реле.
- `mission-down.sh` — свернуть: цели закрываются ДО конца (цикл удаления +
  ассерт), маркеры снимаются, lockdown off, VPN off, хвост канарей-журнала.
- Реле (`artex-bench/vm-lab/relay.py`) в strict-режиме пускает LLM-трафик
  только при armed-маркере: **LLM = заложник состояния миссии**. Блокировки
  пишутся в канарей-журнал как `GATE-BLOCKED`.

## Проверено живьём (2026-10-27, oxint-таргеты)

- lockdown (kill-switch) **совместим с vz-NAT**: под включённым lockdown гость
  ходит в цель (302) и в Venice (402), хост-интернет работает через туннель.
- Посторонний внешний IP из гостя — 000 (blocked) во время миссии.
- strict-без-armed → LLM-блок `GATE-BLOCKED` в журнале; с armed → 402 (Venice).
- down возвращает всё: цель из гостя 000, хост на своём IP, lockdown off.

## Ритуал внешней миссии

```bash
dig +short gw.example.com | grep -E '^[0-9]+\.'   # резолв цели
bash .../mission-up.sh 104.21.43.248 172.67.190.169
# ...миссии в консоли 127.0.0.1:8787 (company+scope задачи), работа...
bash .../mission-down.sh
tail ~/projects/artex-bench/artifacts/canary-relay.log   # все соединения = только Venice
```

## Границы (известно и принято)

- Гость→шлюз vz-NAT (192.168.5.2) = доступ к host-loopback-сервисам; закрыто
  ГОСТЕВЫМ OUTPUT-правилом (DNS/DHCP только), но root-воркер его снимает.
  Хостовые слушатели: реле (8444, без авторизации), LM Studio (1234),
  ssh-туннель. При активной внешней миссии лишние host-сервисы желательно
  не поднимать; LM-туннель — по необходимости (fallback-профиль).
- DNS-канал из гостя идёт через хост-резолвер (под VPN — Mullvad DNS);
  теоретический DNS-exfil остаётся узким принятым риском.
- Пока миссия поднята, VPN отключать нельзя (lockdown режет весь трафик
  хоста вне туннеля) — это фича, не баг.
